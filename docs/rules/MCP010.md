# MCP010: SQL built from tool input

**Severity:** HIGH when a query that looks like SQL is assembled with an f-string, `+`,
`%` or `.format`. MEDIUM when the caller supplies the whole query.

A tool argument ends up inside the query text, so the caller decides what the database
executes. That is SQL injection, or with a caller-supplied query and a privileged
connection, arbitrary database access.

## Vulnerable

```python
from mcp.server.fastmcp import FastMCP
import sqlite3

mcp = FastMCP("demo")

@mcp.tool()
def find(name: str):
    return sqlite3.connect("app.db").execute(f"SELECT * FROM users WHERE name = '{name}'").fetchall()
```

Assembly into a variable, or with `%` / `+` / `.format`, is caught too:

```python
from mcp.server.fastmcp import FastMCP
import sqlite3

mcp = FastMCP("demo")

@mcp.tool()
def find(name: str):
    query = "SELECT * FROM users WHERE name = '%s'" % name
    return sqlite3.connect("app.db").execute(query).fetchall()
```

Handing the whole query to the database is the MEDIUM form:

```python
from mcp.server.fastmcp import FastMCP
import sqlite3

mcp = FastMCP("demo")

@mcp.tool()
def query(sql: str):
    return sqlite3.connect("app.db").execute(sql).fetchall()
```

## Fixed

```python
from mcp.server.fastmcp import FastMCP
import sqlite3

mcp = FastMCP("demo")

@mcp.tool()
def find(name: str):
    return sqlite3.connect("app.db").execute(
        "SELECT * FROM users WHERE name = ?", (name,)
    ).fetchall()
```

Use placeholders and pass the values separately, or use an ORM statement.

## Deliberately not flagged

- A constant query, or a query whose only non-constant part is a placeholder list.
- ORM statements such as `select(User).where(User.name == name)`, including one built
  with an f-string *value*.
- A query builder that returns placeholder fragments and a parameter list.

## Known limits

- The HIGH form needs the query to look like SQL. A string that never says `SELECT`,
  `INSERT`, `UPDATE` or `DELETE` is not assembled-and-reported, which keeps false
  positives down and can also hide a query built from pieces.
- A value validated against a literal allowlist before it is interpolated is still
  reported when it is interpolated as SQL syntax rather than as a value; read the finding.
- If a tool must run caller-supplied SQL, the mitigation is a read-only database role,
  which the scanner cannot see. Suppress the finding and record the role.
