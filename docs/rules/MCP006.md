# MCP006: Unpinned dependency

**Severity:** LOW

A dependency is declared without an exact version, so every install can pull a different
release. A hijacked or broken release reaches the server without anyone changing a file.

## Vulnerable

```text
# requirements.txt
mcp
requests>=2
```

```json
// package.json
{"name": "x", "dependencies": {"@modelcontextprotocol/sdk": "latest"}}
```

## Fixed

```text
# requirements.txt
mcp==1.2.0
requests==2.32.3
```

```json
// package.json
{"name": "x", "dependencies": {"@modelcontextprotocol/sdk": "1.24.0"}}
```

Pin exact versions and keep a lockfile.

## Deliberately not flagged

- A pinned requirement, with `==` for Python or an exact version for npm.
- A package name that merely looks like a secret, such as a dependency called
  `secret-mask`.

## Known limits

- The rule reads `requirements*.txt` (any file whose name starts with `requirements`) and
  the dependency sections of `package.json`. A `pyproject.toml`, `go.mod` or `Dockerfile`
  pinned elsewhere is not checked by this rule.
- A range with a lower bound (`>=2`) is reported, because it still resolves differently
  over time. Some projects pin only in the lockfile on purpose; suppress the finding there.
