# MCP004: Network transport without authentication

**Severity:** HIGH

The server listens over HTTP or SSE and no authentication code is found anywhere in the
project. Anyone who can reach the port can call the tools, which usually means anyone on
the same network. It is worse when the server binds to `0.0.0.0`.

## Vulnerable

```python
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("demo")

@mcp.tool()
def ping():
    return "pong"

mcp.run(transport="sse", host="0.0.0.0", port=8000)
```

A web route that exposes the protocol has the same problem:

```python
from fastapi import FastAPI

app = FastAPI()

@app.post("/mcp/call")
async def call(body: dict):
    return {"ok": True}
```

## Fixed

```python
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("demo")

def check(request):
    return request.headers["Authorization"] == "Bearer " + TOKEN

@mcp.tool()
def ping():
    return "pong"

mcp.run(transport="sse")
```

The fix is authentication, and binding to `127.0.0.1` when the server only serves local
clients. A server that uses the stdio transport is not reported at all, because it is not
reachable over the network:

```python
mcp.run(transport="stdio")
```

## Deliberately not flagged

- A project whose only transport is stdio.
- An HTTP or SSE transport next to authentication code.
- A project that carries other findings, without a network transport of its own.

## Known limits

- The rule looks for authentication in the project, not per route. One authenticated route
  next to an unauthenticated one is not distinguished, so read the finding rather than
  assuming the whole server is protected.
- A project can be reported even when it is only ever started behind a reverse proxy that
  authenticates. Suppress the finding in that case and record why.
