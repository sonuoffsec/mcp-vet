# MCP007: Overly broad filesystem scope

**Severity:** HIGH

An MCP client configuration grants a server access to the filesystem root, a whole home
directory (`/home`, `/users`, `/root`) or a whole drive. A filesystem server is only as
narrow as the directory it is given, so this hands the model every readable file the user
owns.

## Vulnerable

```json
{"mcpServers": {"fs": {"command": "npx", "args": ["-y", "@modelcontextprotocol/server-filesystem", "/"]}}}
```

Granting the home directory, or a drive root, has the same problem:

```json
{"mcpServers": {"fs": {"command": "npx", "args": ["server-filesystem", "~"]}}}
```

## Fixed

```json
{"mcpServers": {"fs": {"command": "npx", "args": ["@modelcontextprotocol/server-filesystem@2025.8.1", "./project"]}}}
```

Scope the server to a single project directory.

## Deliberately not flagged

- A configuration that scopes a filesystem server to a relative project directory.
- An argument that names a directory but is not a broad root, such as `/tmp/build`.
- A client config that launches a local script, such as `node ./dist/server.js`.

## Known limits

- The rule looks at the arguments a server is launched with, in a JSON config, and
  compares them with a fixed list of broad roots: `/`, `~`, `~/`, `/home`, `/users`,
  `/root` and `c:\`. A different drive letter, or a root written some other way, is not
  reported.
- This rule reads client configs alongside [MCP014](MCP014.md); a single config can
  produce both findings.
