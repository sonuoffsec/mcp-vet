# MCP003: Hardcoded secret

**Severity:** CRITICAL

A credential in a known format is committed in source or config. Unlike
[MCP012](MCP012.md), which infers a secret from its name and its shape, this rule matches
publishers' own formats, so a hit is close to certain.

## Vulnerable

```python
{{KNOWN_FORMAT_SECRET}}
```

The recognised formats are AWS access key IDs (`AKIA` plus 16 characters), GitHub tokens
(`ghp_`, `gho_`, `ghu_`, `ghs_`, `ghr_`), Anthropic and OpenAI style keys
(`sk-ant-…`, `sk-…`), Slack tokens (`xoxb-`, `xoxp-`, and the other `xox` prefixes), and
PEM private key headers.

The example above is a placeholder: a page in this repository must not contain a working
token. Any literal value in one of those formats is what the rule reports.

## Fixed

```python
import os

GITHUB_TOKEN = os.environ["GITHUB_TOKEN"]
```

Read the value from the environment or a secret manager at runtime.

## Deliberately not flagged

- A reference to the name of an environment variable, such as
  `API_KEY_ENV = "OPENAI_API_KEY"`.
- A value read from the environment: `PASSWORD = os.environ["DB_PASSWORD"]`.
- A path to a secret file, such as `TOKEN_FILE = "/run/secrets/service_token"`.

## Known limits

- Revoking the credential matters more than the finding: a secret that reached a
  public repository should be rotated even if the commit is later removed.
- Output is redacted, so the report and SARIF file do not copy the secret. The value is
  still in the repository and in its history.
- A secret in an unrecognised format is not reported here. [MCP012](MCP012.md) covers
  some of those cases.
