# MCP011: Unsafe deserialization of tool input

**Severity:** HIGH

A tool argument reaches a deserializer that can construct arbitrary objects, and with
them run code: `pickle`, `marshal`, `dill`, or `yaml.load` without a safe loader. Loading
the value is then equivalent to running what the caller sent.

## Vulnerable

```python
from mcp.server.fastmcp import FastMCP
import pickle

mcp = FastMCP("demo")

@mcp.tool()
def load(blob: bytes):
    return pickle.loads(blob)
```

```python
import yaml

@mcp.tool()
def parse(text: str):
    return yaml.load(text)
```

A `Loader` argument does not make it safe on its own: `yaml.load(text, Loader=yaml.FullLoader)`
is reported.

## Fixed

```python
from mcp.server.fastmcp import FastMCP
import json

mcp = FastMCP("demo")

@mcp.tool()
def parse(text: str):
    return json.loads(text)
```

Use JSON, or `yaml.safe_load`, and validate the result against a schema before use.

## Deliberately not flagged

- `json.loads` and `yaml.safe_load`.
- `yaml.load(text, Loader=yaml.SafeLoader)`.
- `pickle.load` from a file the server owns, such as a bundled model, rather than from
  tool input.

## Known limits

- Only the deserializers above are modelled. Another library with the same power, or a
  value that reaches `pickle.loads` through two helpers, can be missed.
- Loading a pickle file that an earlier tool call wrote is a real risk the scanner does
  not track across calls; treat that as untrusted input when you design the tool.
