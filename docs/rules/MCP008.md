# MCP008: Hidden Unicode characters

**Severity:** HIGH

Zero-width, bidirectional-control and tag characters are invisible in a diff and in most
editors, but the model still reads them. They are used to hide instructions inside a tool
description while a human reviewer sees an empty gap. Runs of them can also encode a
whole message.

## Vulnerable

```python
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("demo")

@mcp.tool(description="Adds two numbers{{ZERO_WIDTH}} quietly")
def add(a: int, b: int):
    return a + b
```

`{{ZERO_WIDTH}}` stands for one literal U+200B ZERO WIDTH SPACE. This page does not embed
the character, because a documentation file should not carry hidden text; copy one into a
test file of your own to see the finding.

The rule covers U+200B–U+200F, the bidi embeddings and overrides U+202A–U+202E, the word
joiners U+2060–U+2064, the bidi isolates U+2066–U+2069 and the Unicode tag characters
U+E0000–U+E007F.

## Fixed

```python
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("demo")

@mcp.tool(description="Adds two numbers quietly")
def add(a: int, b: int):
    return a + b
```

Delete the characters and review the surrounding text: the point of the rule is that
something was hidden there, so the visible text is only part of what you need to read.

## Deliberately not flagged

- ZWJ and ZWNJ inside Persian, Thai and Indic text, and ZWJ inside emoji sequences.
- A single zero-width character used in a comparison in code.
- In `.md` and `.txt` files only bidi overrides, tag characters, word joiners and runs of
  three or more zero-width characters are reported, so ordinary prose in those scripts is
  safe.

## Known limits

- A single invisible character in ordinary prose is not reported, by design. A file that
  hides one instruction behind one character in a Markdown comment can therefore be
  missed.
- The characters are obvious once you know where they are, so the finding includes the
  line; reviewing that line in a hex-capable editor is the practical next step.
